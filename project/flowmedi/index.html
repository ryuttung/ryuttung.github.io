선택 항목의 완료 기준 재정의 및 상태 표현 개선

Problem
선택사항인 Tag도 반드시 채워야 하는 단계처럼 오해할 수 있는 구조
Hypothesis
완료(Completed) 상태는 필수 입력 충족 여부만을 기준으로 표현되어야 한다
Solution
Tag 항목에 ‘optional’ 레이블 명시 후 입력 개수 보여주는 방식으로 변경
Result
-
Lesson Learned
상태 표시는 정책을 전달하는 신호이므로, 정책과 UI의 정합성이 깨지지 않도록 의미를 명확히 설계해야 함

Problem

배송 생성 화면은 필수 입력을 모두 완료해야 ‘Create Shipment’ 버튼이 활성화되는 구조였지만, 선택 항목인 Tag가 1개만 입력되어도 Progress 영역에서 ‘Completed’로 표시되고 있었다. 즉, 실제 정책 기준과 UI 상태 표현이 불일치하는 구조였고, 화면에서는 ‘Completed’라는 상태로 강조되면서 사용자가 Tag도 반드시 채워야 하는 단계처럼 오해할 수 있는 구조였다.

Hypothesis: 완료(Completed) 상태는 필수 입력 충족 여부만을 기준으로 표현되어야 한다.

배송 생성 완료 기준은 사용자가 “배송을 만들기 위해 꼭 해야 하는 것”이 끝났는지를 알려줘야 한다고 판단했다. 따라서 선택 항목인 Tag를 ‘완료(Completed)’로 표시하는 것은 상태 의미를 왜곡하고, 사용자에게 필수 단계처럼 오해를 줄 수 있다고 보았다. 다만 Tag는 검색 편의성을 위해 작성이 권장되는 항목이므로, ‘필수’가 아닌 ‘권장’의 맥락으로 표현을 전환한다면 사용자가 실제 필수 항목을 더 직관적으로 구분할 수 있고 혼선을 줄일 수 있을 것이라고 가설을 세웠다.

Solution

  • Tag 항목에 “(optional)” 레이블을 명시해 선택 항목임을 명확히 표시
  • Progress 영역에서 Tag의 Completed 상태 표시 제거
  • 대신 Tag는 입력 개수를 보여주는 방식(예: 0 added, 2 added 등)으로 변경
  • 완료 기준은 필수 입력 항목 충족 여부로만 판단하도록 구조 정리

    • Lesson Learned

    완료(Completed)와 같은 상태 표현은 진행 상황뿐 아니라 사용자가 정책을 이해하는 기준이 될 수 있다. 따라서 정책과 UI의 정합성이 깨지지 않도록 상태의 의미를 명확히 표현하는 것이 중요하다는 것을 배웠다.
